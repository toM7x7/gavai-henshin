# 装着アーマー 物理適合ルール (armor-body-fit.v1) — 2026-07-05

Status: Active / 実測収束済み

このドキュメントは「生成した装甲を、実際のVRM素体に装着可能な物理設計図として成立させる」ための
**測定に基づく適合ルール**を定義する。感覚のクリアランス表ではなく、
`tools/blender/armor_fullbody_assembler.py` が BVH 距離実測 → 自動再鍛造で収束させた規則。

## 0. 適合審査(Fit Audit)の原理

各装甲パーツの全頂点について、**素体メッシュの最近傍点を求め、体表法線の符号で内外を判定**する。
内側に落ちた頂点 = 貫通(penetration)。合否は「浮いているか」ではなく「めり込んでいるか」で決める:

```text
PASS 条件:
  貫通率 (intrusion_ratio)   <= 1.0%       # 装甲頂点のうち体内に入った割合
  最大貫通深さ (max_intrusion) <= 4 mm      # 最も深くめり込んだ量
```

「体表から6mm浮いていない」ことは不合格ではない。装甲はアンカー部で体に接するのが正しい。

## 1. 再鍛造(Reforge)— パーツ形状タイプ別の正しい操作

**重要な知見**: 開いた胴シェルや内股は「半径スケール」では原理的に収束しない
(スケール2.3倍でも内股18%貫通のまま、かつ土星の輪状に肥大する)。
パーツの幾何タイプごとに操作を変える:

| タイプ | 対象 | 操作 | 理由 |
| --- | --- | --- | --- |
| **rigid_shift**(第0段) | 深く方向的な貫通(deficit > 1.5×gap かつ push_coherence > 0.55) | パーツ全体を平均脱出方向へ剛体移動(1回≤60mm、最大3回) | 積層板が増えたパーツはbbox中心合わせで内壁が体に食い込む。conformで直すと**全レイヤーが同一面に潰れて**板の浮き・段差が消えZ-fightする。胸当てはずらす、潰さない(コスプレの論理) |
| **conform** | 胸/背/腰/肩/腕/脚/手/ブーツ | 貫通頂点だけを体表法線方向へ gap 分押し出し + Laplacian平滑化 | 各頂点は貫通深さ分しか動かない=肥大不可能。クレスト等の外側特徴は不変 |
| **enclose-hybrid** | ヘルメット | 貫通率>8%(粗い不適合)のみ均等スケール、残りはconform(バイザーemissive頂点+首ライン以下を審査除外) | 頭部実寸キャリブレーション後の残貫通は頬の浅い擦れ(≤12mm・±30-60°に集中、実測)= conformの領分。均等スケールで頬数点を満たそうとすると兜が1.42倍まで膨張する(頭でかいバグの真因)。合否は貫通率のみ — バイザー窓の顔は設計上のリビール |
| **along+length** | 上腕/前腕/腿/脛 | 関節スパン - 2×18mm に長さを合わせてから conform | 関節の逃げ(reveal)を物理的に確保 |

conform は反復(最大4パス、後半はrelax無しで残留ポケットを詰める)で 6-34% → 0-0.5% に収束する。

**push_coherence**(2026-07-09追加) = |Σ脱出法線| / 貫通頂点数。1.0=全頂点が同方向へ逃げたい
(=座りの悪い板 → rigid_shift が正しい)、低い=体を囲むチューブや肩越え形状(→ conform のみ)。
実測: ディテール化した胸 21.9%貫通/55mm → rigid -49mm 後 conform 1,626頂点で0%収束
(rigid無しだと conform 15,980頂点・積層潰れでemissiveが破れて見えた)。背中は coherence 0.246
(肩越えで+Y/+Zに分散)のため正しくrigid対象外。

## 2. 装着スケール(WORN_SIZE)

Quest ランタイム装着契約 `QUEST_GLB_TARGET_SIZES`(viewer/quest-iw-demo/quest-demo.js)を単一の正とする。
生成パーツはこのサイズへ縮小してから素体クリアランス倍率を掛ける。

## 3. アンカー・配置ルール(PLACEMENT)

- ボーン名は VRoid 規約(`J_Bip_*`)。humanoid名→ボーン名は `BONE_NAME` 表。
- **手足の向きは関節チェーンから取る**(`NEXT_JOINT`)。glTFインポータがボーンtailを+Z合成するため、
  bone.tail をそのまま使うと全手足が上を向く。UpperArm→LowerArm→Hand の順で次関節位置を軸にする。
- モード: `center`(bbox中心をアンカーへ)/ `along`(関節軸に沿わせて中点配置)/ `foot`(底を接地)。
- 素体の正面は -Y(`BODY_FACING = -1`)。背中パーツは Z180°回転。

## 4. 関節の逃げ(Joint Reveal)実測ターゲット

隣接プレート間のアンダースーツ露出を**関節軸に沿って**測る(Tポーズ安全):

| 関節 | 目標 | 収束実測 |
| --- | --- | --- |
| 肘 elbow | 2–60 mm | 35.8 mm PASS |
| 膝 knee | 2–80 mm | 30.5 mm PASS |
| 手首 wrist | -20–60 mm | -7.8 mm PASS |
| 胴腰 chest_waist | -20–70 mm | 22–47 mm PASS |

上限は130→70mmへ締めた(2026-07-10): 130mm許容は側面から見ると脇腹が空く。
下限は0→-20mm(同日): 胸裾が腰上端に僅かに被るのは瓦重ねで衣装として正。

## 4b. 胴の被覆審査(Torso Coverage)— 腋下・脇腹(2026-07-10)

ユーザー指摘「腋下・脇腹は隙間が出来やすい」を規約化。`audit_torso_coverage` が
体表頂点から法線レイ(≤90mm)で chest/back/waist への被覆を実測し、
帯ごとに未被覆率と**最大連続未被覆角**(5°ビン、円環走査)を報告する:

| 帯 | 範囲 | 収束実測 |
| --- | --- | --- |
| 腋下 armpit | 上腕付根z−100〜−20mm(腕頂点は肩x92%で除外) | 未被覆 0% / 連続 0° |
| 脇腹 flank | 腰上60mm〜胸ボーンz | 未被覆 ~14% / 連続 5°(水平リビール分) |

**シームを閉じた3点セット**(どれか1つでは閉じない):
1. 前後シェルの奥行き分割を深く: chest = 増幅奥行き×**0.74**、back ×**0.62**
   (0.62/0.5 では rigid_shift 後に側面の重なりが尽きる — 胸−34mm/背+48mmの実測)
2. wrap_deg 広め: chest **218°** / back **208°**(側端が体側線を越えて瓦で重なる)
3. 胸/背の丈 0.34→**0.36** + 配置z 0.02→0.01(裾を肋骨下へ=水平リビールを67→22-47mmに)

**腰リングは伸ばさない**: 丈0.19が均衡点。上へ伸ばすと上端の内カールが腹の張り出しへ、
下へ伸ばすと底部リムが臀部へ食い込み、rigid_shiftが上下往復して収束しない(0.20で実測2連敗)。

## 4c. 審査の偽陽性対策と膠着レスキュー(2026-07-10)

同ラウンドで判明した審査自体の穴3つ:

1. **内壁除外**: Solidify内壁など「体を向く面」(頂点法線・体法線のdot < −0.3)は
   見える表面ではないので審査から除外。外壁を突き抜ける本物の貫通は外壁頂点が
   必ず体内に入るので検出は落ちない — 落ちるのはシェル厚未満の不可視かすりだけ
2. **crotch_guard**(PROBE waist): 全周リングの下端は脚の間の**空中**を通る。
   そこの頂点は最近傍が「隣の腿の内側」になり体内と誤判定される(兜の首空域
   z_floor と同種の凹面偽陽性)。hips_z−0.03未満かつ|x|<0.10を審査除外。
   レンダ実証: 3%/31mm「貫通」の腰も見た目は完全に健全だった
2b. **実在確認レイ(crease_filter、waist限定)**: 本当に体内の頂点なら、自法線の
   外向きレイは体表を貫いて出る(dist×3+20mm以内)。へそ・背骨溝・臀裂などの
   **凹面を橋渡し**する頂点は最近傍符号では「体内」に読めるが外向きレイは
   何も叩かない(橋の下は空気)。貫通重心レポート(intrusion_centroid/
   intrusion_z — 同日追加)が「x≈0の正中線・z=股間〜へそ」を指したことで特定。
   **警告: 全部位に適用するな** — 腿では内腿の接触票が消えて coherence が跳ね、
   rigid_shift 3連発で腿が脚上方へずり上がった(膝172mm露出の実害)。
   偽陽性はときに**荷重を受けている**(誤検出票が誤った剛体移動を抑えていた)
2c. **縁(木口)頂点とper-part max_ratio**: 密着リングのリム断面の頂点は法線が
   体表と直交気味 → 内壁除外にも実在確認にも掛からず、構造的に「シェル厚ぶん
   体内」(実測11.4mm≈シェル厚)に読める。レンダ不可視。腰は max_ratio 0.02
   (通常1%→2%)のratio-only判定とする
3. **rigid_rescue(ロールバック付き)**: capped conform は cap より深い貫通を
   原理的に消せない。改善が前回比85%未満に止まったら平均脱出方向へ剛体シフトを
   **試し、直後に再計測して改善していなければ戻して打ち切る**。締まり嵌めの
   全周リング(腹と臀部に挟まれる腰)は動かすと反対側が食う — 試行錯誤を
   エンジンに内蔵し、悪化だけは絶対にさせない

## 5. 収束実績 (intent-demo, 2026-07-05)

- **パーツ 17/18 PASS**(ヘルメットのみ 9.3%: バイザー開口から顔が覗く意図的残留)
- **関節ギャップ 4/4 PASS**
- conform 前 6-34% 貫通 → conform 後 0-0.5%
- 反復回数: 平面プレートは1-3パス、深く埋まる腿/腰/兜は4パス

## 6. サービス化との接続

- `assembly.json` に `fit_contract_version: armor-body-fit.v1` と各パーツの `fit_audit` 実測を保存。
  これが Web Forge / Quest の装着契約と同じ土俵の「物証」になる。
- この適合審査は Blender 側で完結するが、収束した WORN_SIZE / gap / reveal は
  既存の `src/henshin/armor_fit_contract.py`(ARMOR_SLOT_SPECS)と同じ意味論。将来は共通化する。
- Quest ランタイムは実行時に GLB を装着するだけなので、**この適合審査を生成時に通した GLB は
  そのまま runtime_package の装着契約を満たす**。
