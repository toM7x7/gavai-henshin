# ヒーロー比率の文法 — 「でくのぼう」の根治 (2026-07-09)

Status: Active / エンジンコンセプト改訂

## 診断 — ダサさの言語化

ユーザー指摘「パーツ単位では良いが全体が不格好。人間のボディラインが前提としてかっこいい
という視覚効果があり、そのバランスを無意識に判定している」を実測で裏付けた:

| 指標 | 現状実測 | ヒーロー規範 | 症状 |
|---|---|---|---|
| Vテーパー(胸幅/腰幅) | **1.27** | 1.4–1.6 | 寸胴。逆三角形が出ていない |
| 腕装甲径/胸幅 | **0.23** | 0.28–0.30(参照図実測) | 胸だけ過剰で腕が素腕に見える |
| 胸の体からの浮き | 奥行0.14m+前方シフト50mm | 体表+2〜3cm | 「着ている」でなく「板を前に掛けている」 |
| 部品間干渉 | **未計測**(対・体のみ審査) | 干渉ゼロ | 動くと重なりが見える=現実にあり得ない |

根本原因: 各部位が**独立の定数(WORN_SIZE)**で作られ、(1)人体の実寸から導出されていない、
(2)隣接部位と調停されていない、(3)スーツ全体の設計意図(モチーフ・焦点)を持っていない。

## 三原則(エンジンコンセプト)

### 原則1: 人体線第一(Body-line Primacy)
装甲は人体の**置換ではなく増幅**。かっこよさの土台は人間のシルエットそのものであり、
全部位の worn サイズは**素体の実測断面 × ヒーロー増幅率**から導出する(兜キャリブレーションの
全身化)。増幅率は「筋肉の誇張」として意味を持つ:
- 肩・腕・脚 = 大きく増幅(力の表現)
- 胸 = 幅は増幅・**奥行きは抑制**(体に沿う。前に浮く胸は筋肉ではなく板)
- 腰 = 最小増幅(絞る。Vテーパーはここで生まれる)
さらに **Vテーパー・ガード**: 胸幅 ≥ 腰幅×1.45 を契約として強制。

### 原則2: 干渉ゼロの服飾構造(Costume Clearance)
現実のスーツ/コスプレは人間の可動を前提に「ぶつからない」よう裁断される。干渉は
バグではなく**構造設計の欠如**。機能美・構造美は自然(人体と可動)から生まれる:
- **部品間適合審査**(audit_part_overlaps): 隣接ペア(胸-腰、胸-肩、肩-上腕、腰-腿…)の
  相互貫通を対・体審査と同様にBVHで実測し、assembly JSONに記録する。計測が先、規則は後
- 重なりは「重ね(layering)」として設計する: 鎧は屋根瓦 — 上の部品が下の部品の上端を
  覆う方向を規定し、そこは干渉でなく設計上のオーバーラップ(将来: 可動コーンテスト)

### 原則3: 意味の階層(Design Semantics)
「コンセプトがあった上での衣装」にする。装飾は確率でばら撒かない:
- **焦点はスーツに1つ**(胸のコア/エンブレム)+ 顔の主張(バイザー)。他は脇役
- **モチーフ線の連続**: トリム線・色替え線は部位をまたいで同じ高さ・角度で流れる
  (スーツレベルのモチーフパラメータを全部位が参照する)
- 質量の物語: 重装=下半身どっしり / 俊敏=肩から先端へ細く — physiqueを比率の物語に接続

## 実装ステージ

- **Stage 1(実装済み)**: calibrate_worn_from_body — 素体断面の実測(胸・腰スライス、
  四肢のボーン軸半径)→ ヒーロー増幅テーブル → WORN_SIZE/配置を導出。Vテーパー・ガード付き
- **Stage 2(計測実装済み)**: audit_part_overlaps — 隣接部品ペアの貫通率/深さを毎ビルド記録。
  解決(重ね方向の規定+アンダー側トリム)は次ステージ
- Stage 3(次): モチーフ線の連続(コンパイラにスーツレベル・モチーフ)、焦点階層の強制
- Stage 4(次): 可動コーンテスト(腕±60°スイングでの胸-肩-腕クリアランス)

## ヒーロー増幅テーブル v1

| 部位 | 実測元 | 幅 | 奥行 |
|---|---|---|---|
| 胸 | 胸郭スライス(肩関節の内側) | ×1.30 | ×1.32(体に沿う) |
| 腰 | 骨盤スライス | ×1.08 | ×1.10(絞る) |
| 肩 | 上腕径 | ×1.9(+外側オフセット) | ×1.6 |
| 上腕/前腕 | ボーン軸半径 | ×1.55 / ×1.65 | 同 |
| 腿/脛 | ボーン軸半径 | ×1.45 / ×1.55 | 同 |

増幅率が「空気(クリアランス)」を含むため、キャリブレーション済み部位の CLEARANCE は 1.0。

## 実測収束記録(2026-07-09、patrol-01で3ラウンド)

| 指標 | 実装前 | 収束後 |
|---|---|---|
| Vテーパー | 1.27 | **1.45** |
| 肩スパン/頭 | (寸胴補正前) | **3.33** |
| 腕/胸 | 0.23 | **0.33** |
| 腿 vs 脛 | 脛>腿(逆転) | 腿0.213 > 脛0.204 ✓ |

収束までに踏んだ計測の罠(恒久ルール化済み):
1. **四肢計測の汚染**: 半径窓が広いと反対脚・胴の頂点を飲んで象脚になる →
   部位別の半径キャップ+利き側xフィルタ+関節を避けたt範囲(_LIMB_WINDOW)
2. **ガードの向き**: Vテーパーを「腰を絞って」達成すると腰が骨盤未満になり崩壊 →
   **体が下限**。テーパーは胸を育てて作る(waist=体×1.08を確定→chest=max(実測増幅, waist×1.45))
3. **脛は膨らみ込みの実測**なので増幅を控えめに+脛≤腿×0.96ガード

残課題: 腰ベルトの潰れ(conformがベルト装飾を巻き込む — 腰はrigid優先の専用処理へ)、
部品間干渉の「重ね方向」規定と解決(waist~thigh 13-15%はフォールドの設計上オーバーラップ
との切り分けが必要)、Stage 3(モチーフ線・焦点階層)。

## 追補: 機能→装備の演繹(原則3の第一歩、2026-07-09)

「こんな機能があるからこんな小物を付けよう」の行間を埋める文法を実装:
`_GEAR_WORDS`(8機能: patrol/blade/shooter/flight/scan/rescue/comms/stealth)→
`_gear_for`(部位別装備キット)。**飾りは置かない — すべての小物は言葉が主張した
機能の痕跡**(剣士→背の鞘帯+腰の留め具+受けの籠手、飛行→脛後ろのスラスタ+排気+
背の姿勢制御フィン、救助→背タンク対+警告灯+ベルトの缶)。ルートB規範にも同文。

同時に直した評価インフラ: ①背面ビューをレンダに追加(背面装備はfront/3q/sideに写らない)
②パレット・コントラストガード(base≒accentの単色化を輝度差<0.22で検出し反対極へ)
③**_DEFAULT_MODULESが4部位だった問題**(ルートAは背・腰・四肢を最初から設計して
おらず素の筒が建っていた — 数週間の「脚がのっぺり」の真因)→フル12部位へ。
